# ColorToMQTT

[![CI](https://github.com/Mkilord/color-to-mqtt/actions/workflows/ci.yml/badge.svg)](https://github.com/Mkilord/color-to-mqtt/actions/workflows/ci.yml)

Spring Boot приложение, которое следит за цветом в центре экрана и отправляет его в MQTT. Подходит для подсветки в умном доме: лампа повторяет цвет того, что сейчас на экране.

## Как работает

После запуска приложение повторяет цикл с паузой `framePeriodMs` мс между кадрами:

1. Снимает область в центре экрана размером `width` x `height` через `java.awt.Robot`. Если область больше экрана, она обрезается.
2. Берет пиксели в узлах сетки с шагом `cellSize` (в шахматном порядке или в каждой клетке) и считает по ним цвет выбранным способом:
   - преобладающий цвет (по умолчанию): цветные точки раскладываются по секторам тона, берется самый весомый сектор с соседними. Темный фон и серые элементы не учитываются, поэтому красный объект на темном фоне дает красный, а не грязно-серый. Если цветных точек меньше `minSharePercent` процентов, берется простое среднее;
   - среднее с упором на яркие цвета: каждая точка весит насыщенность x яркость, несколько цветов смешиваются;
   - простое среднее по всем точкам.
3. Делит цвет на черный, серый и цветной по порогам `blackThreshold` (яркость) и `grayThreshold` (насыщенность). Черный приводится к 0, 0, 0, серый к чистому серому той же яркости: у таких цветов тон определяется шумом и иначе прыгал бы от кадра к кадру.
4. Ждет, пока цвет продержится `holdTimeMs` мс: если за это время цвет снова сменился, отсчет начинается заново. Так короткие вспышки (черный, красный на миг, зеленый) не доходят до ламп и не вызывают мигания. Затем сравнивает цвет с последним отправленным. Переход между черным, серым и цветным отправляется независимо от допусков. Первый кадр после запуска тоже отправляется всегда. По умолчанию сравнение идет в HSB: если разница по тону, насыщенности или яркости больше допуска, цвет считается новым. Тон сравнивается по кругу.
5. Поправляет тон по опорным цветам, усиливает насыщенность, сдвигает H, S, B на заданные значения (тон по кругу) и ограничивает их диапазонами `ranges`. Черный уходит как `{"hue":0,"sat":0,"brightness":0}` без сдвига и ограничений, у серого сдвигается и ограничивается только яркость, тон равен 0, а насыщенность 1: при насыщенности 0 лампы переключаются в режим цветовой температуры со своим оттенком белого, а так остаются в цветном режиме.
6. Публикует цвет в топик MQTT с QoS 0. Соединение с брокером одно на весь сеанс; при обрыве клиент переподключается сам, а после восстановления связи уходит текущий цвет.

Формат сообщения:

```json
{"hue":210,"sat":64,"brightness":48}
```

`hue` в градусах 0..360, `sat` и `brightness` в процентах 0..100. Яркость 0 означает черный экран: в Home Assistant на нее удобно выключать светильники.

## Требования

- JDK 22
- Maven
- Графический рабочий стол: снимок экрана делается через AWT, на headless-сервере приложение работать не будет
- MQTT-брокер, например Mosquitto

## Запуск

Для постоянной работы на Windows:

```bat
start.cmd
```

Скрипт при первом запуске собирает `target\color-to-mqtt.jar` и запускает его одним процессом Java с ограничением памяти (`-Xmx128m`, Serial GC). После обновления кода нужна пересборка: `start.cmd build`.

Для разработки:

```bash
mvn spring-boot:run
```

`mvn spring-boot:run` держит два процесса: сам Maven и приложение, каждый около 150 МБ. Приложению передаются те же ограничения памяти, но Maven остается рядом все время работы. В собранном jar нет и spring-boot-devtools.

Логин и пароль MQTT задаются на странице настроек. Начальные значения можно передать переменными окружения `MQTT_BROKER`, `MQTT_TOPIC`, `MQTT_USERNAME`, `MQTT_PASSWORD`.

Веб-интерфейс откроется на http://localhost:8080. Есть светлая и темная темы: по умолчанию берется тема системы, переключатель в шапке запоминает выбор.

На главной странице:

- текущий цвет на мониторе и его значения в HEX, RGB и HSB;
- состояние захвата и соединения с брокером, топик, последнее отправленное сообщение и время отправки;
- скорость захвата: кадры в секунду, время снимка экрана и время расчета;
- кнопка запуска и остановки захвата;
- сообщение об ошибке, если брокер недоступен или не удался снимок экрана, с подсказкой, что проверить.

На главной же выбирается профиль настроек: например, «Игры», «Фильмы», «Ночь». Смена профиля сразу применяется к идущему захвату.

На странице `/settings`:

- профили: выбор профиля для редактирования, создание (копией текущего или с настройками по умолчанию), переименование, удаление, выбор активного;
- простой режим с основными настройками: подключение к MQTT, размер области, усиление насыщенности, максимальная яркость, оттенки ламп, сглаживание вспышек;
- расширенный режим со всеми остальными параметрами. Параметры, отличающиеся от значений по умолчанию, отмечены точкой, их можно вернуть к умолчанию одной кнопкой;
- панель проверки рядом с формой: снимок области с отмеченными точками, которые вошли в цвет, выбор проверочного цвета (HEX, ползунки тона, насыщенности и яркости, чистые цвета), цвет до и после коррекции, сообщение MQTT и кнопка отправки цвета на лампы.

Сохранение не перезагружает страницу: ошибки показываются у полей, страница остается на месте.

## Настройка

Все параметры меняются на странице настроек. Значения профиля по умолчанию заданы в коде (`ProfileSettings.DEFAULTS`), подключение до первого сохранения берется из переменных окружения:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MQTT_BROKER` | Адрес брокера | `tcp://localhost:1883` |
| `MQTT_TOPIC` | Топик для публикации | `colorToMQTT` |
| `MQTT_USERNAME` | Пользователь брокера | пусто |
| `MQTT_PASSWORD` | Пароль брокера | пусто |

Настройки хранятся в YAML в папке `app.storage-dir` (по умолчанию рабочая директория):

- `settings.yaml`: подключение к MQTT (общее для всех профилей) и имя активного профиля;
- `profiles/<имя>.yaml`: только параметры, отличные от умолчаний. Пустой файл означает профиль по умолчанию, а новые умолчания из следующих версий доходят до старых профилей сами.

Пример профиля:

```yaml
capture:
  width: 640
correction:
  hueShifts:
    green: -20
sending:
  holdTimeMs: 200
```

| Раздел | Параметры |
|---|---|
| `capture` | `width`, `height`: область в центре экрана, px. `cellSize`: шаг сетки, px. `sampling`: `CHESS` (шахматный порядок) или `GRID` (каждая клетка). `framePeriodMs`: пауза между кадрами. `idlePeriodMs`: пауза, если экран не меняется 3 секунды, 0 отключает |
| `detection` | `method`: `DOMINANT` (преобладающий цвет), `VIVID` (среднее с упором на яркие), `AVERAGE` (простое среднее). `minSharePercent`: меньше этой доли берется простое среднее. `blackThreshold`: ниже яркость 0, лампы гаснут. `grayThreshold`: ниже уходит белый в цветном режиме |
| `correction` | `saturationBoost`: усиление насыщенности, %. `hueShifts` (`red`, `yellow`, `green`, `cyan`, `blue`, `magenta`): поправка тона опорных цветов, градусы. `hueShift`, `saturationShift`, `brightnessShift`: общий сдвиг. `ranges` (`hue`, `saturation`, `brightness` с `min`, `max`): диапазоны после сдвига |
| `sending` | `holdTimeMs`: сглаживание вспышек, 0 отключает. `comparison`: `HSB_TOLERANCE`, `RGB_DISTANCE` или `ANY_CHANGE`. `hueTolerance`, `saturationTolerance`, `brightnessTolerance`: допуски, доли 0..1. `rgbThresholdPercent`: порог для сравнения в RGB |

Границы значений проверяются при сохранении, ошибки показываются у полей формы. Если файл профиля исправлен руками с ошибкой, страница сообщит, какой файл поврежден.

При первом запуске старые `settings.txt` и `profiles/*.properties` переносятся в YAML, а сами файлы переименовываются в `.bak`. Значения вне допустимых границ заменяются умолчаниями.

Если захват запущен, сохранение активного профиля, смена профиля или подключения перезапускают его. Сброс профиля возвращает его к умолчаниям и не трогает подключение.

Логин и пароль MQTT хранятся в `settings.yaml` открытым текстом, поэтому файл стоит держать только на своем компьютере. Пароль не выводится на странице и в логах: пустое поле оставляет сохраненный пароль, очистка логина удаляет и пароль.

## HTTP API

| Запрос | Ответ |
|---|---|
| `POST /api/capture/start`, `/api/capture/stop` | Запуск и остановка захвата, `{"message": ...}` |
| `GET /api/status` | Состояние захвата: `running`, `color`, `broker`, `topic`, `connected`, `lastPayload`, `lastSentAt`, `error`, `errorAt`, `performance` (`fps`, `captureMs`, `processMs`, `idle`) |
| `POST /api/test-color` | Отправляет на лампы цвет `{"hue":120,"sat":100,"brightness":40}` как есть, без коррекции |
| `GET /api/profiles` | Профили и активный профиль. `POST /api/profiles` (`name`, `copyFrom`) создает, `/activate`, `/rename`, `/delete` меняют |
| `GET /api/screen` | Размер экрана `{"width":..., "height":...}`, 503 без графической среды |
| `GET /api/snapshot?width=&height=` | Снимок области захвата заданного размера, JPEG |

Ошибки приходят в виде `{"error": "текст"}`: 404 профиль не найден, 409 имя занято или удаляется последний профиль, 422 недопустимые значения (еще `errors` по полям формы), 503 нет экрана или брокера.

## Структура

```
src/main/java/ru/mkilord/colortomqttapp/
  domain           настройки профиля, подключение, имя профиля, цвет; проверка границ и ошибки
  core             алгоритмы без Spring
    capture        снимок области экрана (интерфейс)
    sampling       обход точек кадра
    detection      расчет цвета кадра
    tracking       изменился ли цвет, сглаживание вспышек
    correction     черный и серый, поправки и диапазоны, цвет для ламп
    publishing     сообщение и отправка (интерфейсы)
    pipeline       цикл захвата, собирается билдером
  infrastructure   реализации: снимок через AWT, MQTT (Eclipse Paho), хранилище YAML
  application      сценарии: профили, подключение, запуск захвата
  web              страницы Thymeleaf, JSON API, перевод исключений в ответы
  config           свойства app.* и настройка Spring
src/main/resources/
  templates        страницы и общие фрагменты (шапка, тема)
  static/js        тема, статус на главной, проверка цвета в настройках
  static/styles    стили обеих тем
```

Роли слоев:

- `domain` знает границы значений и бросает `SettingsValidationException` со всеми нарушениями сразу. Контроллеры и форма проверок не дублируют.
- `core` не зависит от Spring: способы расчета и сравнения выбираются по значению перечисления, новый способ добавляется веткой в `switch`, и компилятор не даст ее пропустить.
- Внешние зависимости (экран, MQTT, файлы) скрыты за интерфейсами `ScreenCapture`, `ColorPublisherFactory`, `SettingsStore` и внедряются Spring. В тестах их заменяют простыми реализациями.
- `application` публикует `SettingsChangedEvent`, `CaptureService` по нему перезапускает захват.
- `web` переводит исключения в HTTP-ответы в одном месте, `ApiExceptionHandler`.

## Тесты

```bash
mvn verify
```

Unit-тесты покрывают обработку кадра, расчет цвета, трекеры, сдвиг и ограничения, черные и серые кадры, формат сообщения MQTT, профили и подключение, хранилище YAML с переносом старых файлов, цикл захвата с ошибками и повторной отправкой, страницу настроек, API профилей и статуса. GitHub Actions запускает сборку и тесты на каждый push.
